## Version 5.0

### 학습용 상품 구매·주문

로그인한 일반 사용자는 판매 중인 상품 상세 화면에서 현재 비밀번호를 다시
입력해 학습용 잔액으로 상품을 구매할 수 있습니다. 구매가 완료되면 구매자의
잔액이 판매자에게 이동하고 `결제 완료` 주문이 생성됩니다.

- 구매 경로: 상품 상세 `/product/<product_id>`의 `학습용 잔액으로 구매`
- 주문 내역: `/orders`
- 권한: 관리자·사업자 계정은 구매할 수 없고 일반 사용자만 구매 가능
- 상품 상태: 구매 완료 상품은 공개 판매 목록에서 제외
- 테스트 상품: `사과 한 상자`, `바나나 한 송이`

사용 흐름:

1. `user1`로 로그인해 상품 상세를 엽니다.
2. 현재 학습용 잔액과 상품 가격을 확인합니다.
3. 현재 비밀번호를 입력하고 구매합니다.
4. 주문 내역에서 구매 완료 상태를 확인합니다.
5. 판매자 계정으로 주문 내역을 열어 판매 완료 내역을 확인합니다.

관련 파일:

- `app.py`
- `templates/view_product.html`, `templates/orders.html`, `templates/base.html`
- `tests/test_purchase_security.py`

제한사항:

- 주문·결제는 실제 현금이나 외부 결제 서비스와 연결되지 않는 학습용 기능입니다.
- 상품당 한 번만 구매할 수 있으며 취소·환불·배송·재고 수량·분쟁 처리는 없습니다.
- 주문 상태는 현재 `paid` 하나만 제공하고, 구매 완료 원장은 수정·삭제할 수
  없습니다.

## Version 4.2

### 일반 사용자와 관리자·사업자 송금 권한 분리

송금은 일반 사용자 계정 사이에서만 허용합니다. 관리자·사업자 역할 계정은
송금 메뉴와 처리 경로에 접근할 수 없고, 일반 사용자가 관리자·사업자 계정으로
송금할 수도 없습니다. 일반 사용자 `user1`, `user2`는 계속 양방향으로 송금할 수
있습니다.

- 적용 경로: `/transfers`, 송금 수취인 목록과 처리 API
- DB 보호: 송금 참여자 Trigger에서 `is_admin = 0` 확인
- 검증: `tests/test_transfer_security.py`

## Version 4.1

### 송금 내역 표시 최소화

`/transfers`의 송금 내역은 `보냄` 또는 `받음` 방향과 금액만 표시합니다. 상대방
사용자명, 메모, 내부 처리 시각은 화면에 노출하지 않습니다. 송금 처리와 당사자
접근 제어는 Version 4.0의 원장·권한 정책을 그대로 사용합니다. 관리자는 송금
메뉴와 처리 경로에 접근할 수 없고, 일반 사용자끼리는 양방향 송금이 가능합니다.

- 관련 화면: `templates/transfers.html`
- 검증: `tests/test_transfer_security.py`
- 제한: 실제 금전 이동이나 상품 주문·결제와 연결되지 않는 학습용 원장입니다.

## Version 4.0

### 사용자 간 학습용 송금

로그인한 사용자가 다른 활성 사용자에게 학습용 잔액을 송금하고 본인이 보내거나
받은 내역을 확인할 수 있습니다.

- 송금·내역 화면: `/transfers`
- 접근 권한: 로그인했고 탈퇴·휴면 상태가 아닌 사용자
- 금액 범위: 건당 1원~10,000,000원의 정수
- 메모: 선택 입력, 최대 100자
- 내역: 페이지당 20건

사용 흐름:

1. 상단 `송금` 메뉴에서 현재 학습용 잔액을 확인합니다.
2. 최대 100명의 활성 사용자 목록에서 받는 사용자를 선택합니다.
3. 금액, 선택 메모와 현재 비밀번호를 입력합니다.
4. 서버가 CSRF, 재인증, 송금 횟수, 받는 사용자 상태와 잔액을 다시 확인합니다.
5. 하나의 추가 전용 송금 레코드를 저장하고 보낸 사람과 받는 사람의 잔액을
   원장에서 계산합니다.

본인 송금, 존재하지 않거나 탈퇴·휴면인 사용자, 잔액 초과, 범위 밖 금액,
개인정보가 포함된 메모를 거부합니다. 같은 요청 ID를 다시 전송해도 송금은 한
번만 기록됩니다. 송금 내역은 당사자만 볼 수 있고 계정 탈퇴 이후에도 당시
사용자명 Snapshot을 보존합니다. 잔액이 남아 있으면 회원 탈퇴할 수 없습니다.

### 간단 테스트용 잔액

일반 회원가입 계정의 초기 잔액은 0원입니다. 다음 빠른 실행 명령에서만 두 일반
사용자 `user1`, `user2`에 각각 100,000원의 학습용 잔액을
추가합니다.

```sh
./scripts/quickstart_demo.sh
```

`user1`로 로그인한 뒤 `/transfers`에서 `user2`를 선택하면 외부
서비스나 실제 계좌 없이 송금 흐름을 확인할 수 있습니다. 테스트 잔액과 송금
내역은 서버 종료 시 임시 DB와 함께 삭제됩니다. `user2`에서 `user1`로도
반대 방향 송금이 가능합니다. 상품 목록에는 `user1`의 `사과 한 상자`와
`user2`의 `바나나 한 송이`를 함께 준비합니다.

관련 파일:

- `app.py`
- `templates/base.html`, `templates/transfers.html`
- `scripts/quickstart_demo.py`
- `tests/test_transfer_security.py`, `tests/test_quickstart_demo.py`

데이터 변경:

- 사용자별 원장 계정을 나타내는 `wallet_account`
- 빠른 실행 잔액의 출처를 추가 전용으로 기록하는 `wallet_adjustment`
- 보낸 사람·받는 사람·금액·메모·사용자명 Snapshot을 보존하는
  `money_transfer`
- 송금 사용자·IP 횟수 제한을 위한 `security_rate_limit` 범위 확장

제한사항:

- 모든 잔액은 보안 학습용 정수 데이터이며 실제 원화, 예금 또는 전자지급수단이
  아닙니다.
- 일반 계정의 충전·출금과 운영자 잔액 조정 기능은 제공하지 않습니다.
- 토스페이먼츠 결제·지급대행 API, 실제 은행 계좌, 웹훅과 외부 정산은 연동하지
  않았습니다.
- 실제 금전을 취급하려면 전자금융 관련 계약·법률 검토, 본인확인·KYC/AML,
  외부 원장 대사, 이상거래 탐지, 취소·분쟁·복구 절차가 별도로 필요합니다.

## Version 3.2

### 통합 관리자 페이지

기존의 제재 중심 화면 명칭을 전체 관리 기능을 나타내는 `관리자 페이지`로
변경했습니다. 관리자는 상단 메뉴에서 `/admin`으로 이동해 다음 기능을 한곳에서
사용합니다.

- 상품 목록과 신고 수 확인 및 관리 삭제
- 사용자 목록과 신고 수 확인 및 휴면·재활성화
- 신고 사유와 처리 상태 확인 및 완료·반려
- 최근 관리자 처리 감사 이력 조회

로그인과 `is_admin=1` 역할을 모두 확인한 관리자만 접근할 수 있습니다. 기존
`/admin/moderation` 주소도 같은 권한 검사를 거친 뒤 `/admin`으로 이동하므로
저장된 북마크는 계속 사용할 수 있습니다. 상태 변경 경로와 CSRF·재인증·감사
정책은 Version 3.1과 동일하게 유지합니다.

### 관리자·일반 사용자 빠른 실행

저장소 루트에서 다음 한 줄로 격리된 실습 환경을 실행할 수 있습니다.

```sh
./scripts/quickstart_demo.sh
```

도구는 Conda의 `secure_coding` 환경을 선택하고 저장소 밖 임시 디렉터리에 별도
DB를 만듭니다. 무작위 비밀번호와 Argon2id 해시를 사용하는 `quick_admin`,
`quick_user`, 샘플 상품과 신고를 준비하며 종료 시 임시 DB를 삭제합니다.
일반 실행용 `market.db`는 읽거나 변경하지 않습니다.

관련 파일:

- `app.py`
- `templates/base.html`, `templates/admin_dashboard.html`
- `scripts/quickstart_demo.py`, `scripts/quickstart_demo.sh`
- `tests/test_admin_moderation_security.py`, `tests/test_quickstart_demo.py`
- `docs/QUICK_START.md`, `docs/ADMIN_QUICK_START.md`, `docs/TESTING.md`

제한사항:

- 빠른 실행 계정은 로컬 실습 전용이며 서버 종료 후 유지되지 않습니다.
- 실제 운영 관리자 계정은 일반 계정을 만든 뒤 로컬 역할 관리 도구로 명시적으로
  권한을 부여해야 합니다.
- 개발 서버와 빠른 실행 도구는 실제 운영 배포 방식이 아닙니다.

## Version 3.1

### 신고 검토와 관리자 작업 강화

관리자 제재 화면에서 개별 신고 사유와 현재 처리 상태를 확인하고 신고를
`처리 완료` 또는 `기각`으로 검토할 수 있습니다.

- 관리 화면: `/admin/moderation`
- 신고 검토: `/admin/reports/<신고 UUID>/review`
- 상품 관리 삭제: `/admin/products/<상품 UUID>/remove`
- 사용자 휴면·해제: `/admin/users/<사용자 UUID>/dormant`,
  `/admin/users/<사용자 UUID>/reactivate`
- 로컬 역할 관리: `scripts/admin_user.py`

사용 흐름:

1. 관리자가 대기 중인 신고의 대상과 신고 사유를 확인합니다.
2. 현재 비밀번호와 10~500자의 검토 사유를 입력합니다.
3. 처리 완료 또는 기각 상태를 선택합니다.
4. 처리자 이름 Snapshot, 상태, 사유와 시각을 추가 전용 기록으로 보존합니다.

관리 작업은 로그인 직후 또는 최근 비밀번호 확인 후 5분 동안 허용합니다. 그
이후에는 현재 비밀번호를 다시 요구하며 계정별 10분에 20건으로 제한합니다.
상품 제재 시 제목·설명·가격·판매자 Snapshot을, 제재 감사에는 관리자명과 대상
표시명 Snapshot을 함께 보존합니다. 관리자 역할 부여·해제도 운영자·대상·사유·
시각을 감사하고 대상의 기존 세션을 무효화합니다. 관리자 계정은 역할을 먼저
해제해야 회원 탈퇴할 수 있습니다.

### 회원·상품 남용 방지와 안전한 조회

- 회원가입: IP별 1시간에 5회
- 로그인: IP별 15분에 20회
- 마이페이지 비밀번호 재확인: 사용자·IP별 15분에 10회
- 상품 등록: 사용자별 1시간에 10개, 전체 보유 100개
- 상품·관리자 목록: 페이지당 20건
- 1대1 채팅 상대: 페이지당 100명
- 1대1 채팅 기록: 페이지당 100건

사용자명은 ASCII 영문·숫자와 `_.-`만 허용하고 알려진 단순 비밀번호를
거부합니다. 소개글과 상품 설명의 숨은 Unicode 제어·서식 문자도 거부합니다.
임시 잠금 계정의 소유자는 올바른 비밀번호로 즉시 복구할 수 있어 제3자가 반복
실패로 특정 계정을 계속 잠그는 문제를 줄였습니다.

상품 목록·내 상품 관리·사용자 목록·대화 기록과 관리자 화면에
페이지네이션을 적용했습니다. 상품·신고 대상 조회 인덱스를 추가하고 관리자
화면의 신고 수 계산을 묶음 집계로 변경했습니다. 관리 삭제와 동시에 발생하는
상품 수정은 저장 SQL에서 다시 제재 상태를 확인해 거부합니다.

### 1대1 채팅 차단

대화 화면에서 상대 사용자를 차단하거나 차단 해제할 수 있습니다.

- 차단: `/chat/<사용자 UUID>/block`
- 차단 해제: `/chat/<사용자 UUID>/unblock`
- 로그인과 CSRF Token이 필요합니다.
- 어느 한쪽이 차단하면 양방향 직접 메시지 전송을 거부합니다.
- 차단 상태는 대화 상대 목록과 대화 화면에 표시합니다.

Socket 연결은 Origin이 반드시 있어야 하며 IP별 1분에 20회, 사용자별 동시
5개로 제한합니다.

## Version 1.4

### 신고 접수 운영 보호

신고 기능에 사용자·IP별 시도 제한, 거부 사유 감사 기록과 개인정보 입력 차단을
추가해 운영자가 신고 남용과 실패 이력을 확인할 수 있는 기반을 마련했습니다.

- 사용자와 IP 기준 신고 시도 횟수 제한
- 속도 제한, 중복, 자기 신고 등 거부 결과 감사 기록
- 이메일, 전화번호 및 주민등록번호 형태의 개인정보 입력 차단
- 신뢰할 프록시 수를 명시하는 클라이언트 IP 처리

관련 파일:

- `app.py`의 신고 제한·감사·개인정보 검증 함수
- `tests/test_report_security.py`

### 데이터베이스 백업·검증·복구 도구

신고 및 사용자 데이터가 포함된 SQLite 데이터베이스를 저장소 밖에서 안전하게
백업하고 복구 가능성을 점검하는 명령줄 도구를 추가했습니다.

- 기존 파일을 덮어쓰지 않는 신규 백업 생성
- 백업과 복구 파일의 SQLite 무결성 및 외래키 검사
- 별도 파일로 복구하여 운영 DB 자동 교체 방지
- 결과 파일 권한을 `600`으로 제한

관련 파일:

- `scripts/database_backup.py`
- `tests/test_database_backup.py`
- 사용법: [README.md](../README.md#8-데이터베이스-백업과-복구-검증)

데이터·환경 변경:

- 신고 제한 상태와 실패 감사 정보를 저장하는 기존 신고 관련 스키마를
  확장했습니다.
- 백업 도구를 위한 새 외부 패키지와 환경변수는 없습니다.

현재 제한사항:

- 자동 예약 백업, 원격 보관, 암호화 및 보존 주기 관리는 포함하지 않습니다.
- 애플리케이션을 중지한 상태에서 운영자가 직접 실행해야 합니다.

## Version 1.3

### 사용자·상품 신고 접수

Version 1.0의 단순 신고 입력을 실제 사용자 또는 상품을 대상으로 접수하는
기능으로 강화했습니다.

- 접근 경로: `/report`
- 사용자 또는 상품 중 하나를 신고 대상으로 선택
- 대상 UUID와 신고 사유 입력
- 정상 신고와 접수 시각 저장
- 중복 신고, 자기 계정 및 자신의 상품 신고 차단
- 정상 접수 감사 기록
- 신고자별 시간당 정상 신고 횟수 제한

관련 파일:

- `app.py`의 신고 검증·저장·제한 함수와 `report`
- `templates/report.html`
- `tests/test_report_security.py`

데이터·환경 변경:

- 사용자·상품 대상을 분리해 참조하는 신고 테이블과 감사 로그를 구성했습니다.
- 새 외부 패키지와 환경변수는 없습니다.

현재 제한사항:

- 관리자의 신고 목록, 검토, 승인·반려 및 처리 상태 변경 화면은 없습니다.
- 별도의 안전 거래, 결제 또는 분쟁 조정 기능은 포함하지 않습니다.

## Version 1.2

### 상품 등록·조회·수정·삭제

기존 상품 등록과 목록·상세 조회에 판매자 본인의 수정·삭제 기능을 추가하고,
상품 데이터를 일관된 형식으로 관리하도록 개선했습니다.

- 접근 경로: `/product/new`, `/product/<product_id>`
- 수정 경로: `/product/<product_id>/edit`
- 삭제 경로: `/product/<product_id>/delete`
- 제목, 설명 및 정수 가격을 입력해 상품 등록
- 대시보드에서 전체 상품 목록 조회
- 상품 상세에서 판매자 정보 조회
- 상품 소유자에게만 수정·삭제 기능 표시 및 허용

관련 파일:

- `app.py`의 상품 라우트와 검증 함수
- `templates/new_product.html`
- `templates/view_product.html`
- `templates/edit_product.html`
- `tests/test_product_security.py`

데이터·환경 변경:

- 상품 가격을 `INTEGER`로 관리하고 판매자 외래키와 데이터 제약을 적용했습니다.
- 새 외부 패키지와 환경변수는 없습니다.

현재 제한사항:

- 상품 이미지, 카테고리, 검색, 판매 상태 및 거래 완료 처리는 없습니다.

## Version 1.1

### 회원·로그인·프로필·세션 기능 강화

Version 1.0의 회원 기능을 유지하면서 입력 검증, 비밀번호 해시, 세션 만료,
로그인 실패 제한과 프로필 재인증을 적용했습니다.

- 회원가입과 로그인
- CSRF 보호 로그아웃
- 로그인한 사용자의 프로필 소개글 변경
- 프로필 변경 전 현재 비밀번호 확인
- 30분 유휴 및 8시간 절대 세션 만료
- 로그인 5회 실패 시 15분 계정 잠금

관련 파일:

- `app.py`의 회원·세션·프로필 함수
- `templates/register.html`
- `templates/login.html`
- `templates/profile.html`
- `tests/test_account_security.py`

데이터·환경 변경:

- 사용자 테이블에 로그인 실패 횟수와 잠금 만료 시각을 추가했습니다.
- `argon2-cffi`, `pytest`와 세션·쿠키 관련 환경변수를 추가했습니다.

## Version 1.0

### 최초 기준 기능

[ugonfor/secure-coding](https://github.com/ugonfor/secure-coding)에서 가져온 기반
코드에 다음 기본 기능이 있었습니다.

- 회원가입, 로그인 및 로그아웃
- 대시보드와 전체 상품 목록
- 프로필 소개글 수정
- 상품 등록과 상세 조회
- Socket.IO 전체 채팅
- 신고 입력

데이터·환경:

- SQLite의 사용자, 상품 및 신고 데이터를 사용했습니다.
- 현재 버전의 마이그레이션·제약보다 단순한 초기 스키마였습니다.

Version 1.0은 보안 개선 전 학습 기준입니다. 기능은 동작했지만 평문 비밀번호,
CSRF 미적용, 서버 입력 검증 부재 등 알려진 취약점이 있었으므로 현재 코드와
동일한 안전성을 갖는 버전으로 보지 않습니다.

## 다음 버전 작성 규칙

기능을 추가·변경·제거한 버전은 최신 버전을 이 문서 위쪽에 추가하고 다음 항목을
기록합니다.

1. 기능 이름과 사용 목적
2. 사용자가 접근하는 화면, 경로 및 주요 흐름
3. 로그인, 소유자 또는 관리자 등 접근 권한
4. 관련 코드·템플릿·테스트 파일
5. 데이터베이스, 의존성 또는 환경변수 변경 여부
6. 현재 포함하지 않은 기능과 알려진 제한사항

보안 조치의 구현 세부사항을 이 문서에 중복 작성하지 않습니다. 기능과 직접
연결된 권한·보안 특성만 간단히 설명하고 상세 근거는
`SECURITY_CHANGELOG.md`로 연결합니다.
